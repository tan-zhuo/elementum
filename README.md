# Elementum · 3D 交互式元素周期表

纯前端的化学可视化站点，分为两个板块（顶部菜单切换）：

- **元素周期表** —— 118 种元素，点击查看 **3D 原子结构**（Bohr 模型风格：原子核 + 电子层 + 绕核运动的电子）
- **分子** —— 53 种常见分子（水、氧气、二氧化碳、甲烷、苯、富勒烯……），点击查看**真实三维分子结构**

无后端、无外部 API，`npm run build` 后可直接静态部署。

---

## 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 输出到 dist/，可直接静态托管
npm run preview    # 本地预览生产构建
```

其他脚本：

```bash
npm run typecheck  # TypeScript 严格模式检查
npm run lint       # oxlint
npm run build:data # 重新生成 elements.json 与 molecules.json
```

`vite.config.ts` 中设置了 `base: './'`，因此构建产物使用相对路径，可直接部署到
Vercel / Cloudflare Pages / GitHub Pages（包括子路径项目站点）。

## 功能

**周期表主界面**
- 完整 118 种元素，标准 18×10 布局，镧系/锕系单独成行（主表内保留 `57-71` / `89-103` 占位标记）
- 按 10 个类别着色，悬停高亮 + 信息浮层，点击打开详情面板
- 顶部搜索：元素符号、中文名、英文名、原子序数（带相关度排序，`/` 聚焦，回车打开最佳匹配）
- 类别图例可点击筛选，一键清除
- 属性热力图：相对原子质量、密度、熔点、沸点、电负性、第一电离能、电子亲和能、原子半径

**元素详情**
- **作用与生活应用**：每个元素都有一段说明它到底有什么用，外加若干条具体到能在生活里
  指认出来的应用（如铁：钢筋桥梁、血红蛋白、变压器铁芯、补铁剂）
- 基本信息、电子排布式（完整式 + 惰性气体简写式）、分层电子数、质子/中子/电子数
- 物理化学性质、维基百科简介与链接
- 键盘：`←` `→` 切换相邻元素，`Esc` 关闭
- 复制信息到剪贴板；最多 3 个元素并排对比

**3D 原子结构**
- 电子层数量与每层电子数严格来自真实 `shells` 数据
- 每层一个轨道环，颜色区分，倾角按黄金角分布，保持"同心可数"的同时呈现立体感
- 内层电子转速更快（呼应 Bohr 模型 v ∝ 1/n），相邻层反向旋转
- 拖拽旋转 / 滚轮缩放 / 自动旋转 / 电子运动开关 / 电子云 / 重置视角 / 全屏

**分子板块**
- 53 种常见分子，按单质(11) / 无机物(21) / 有机物(21) 分组，类别可点击筛选
- 覆盖常见气体与酸、VSEPR 典型构型（正四面体 CH₄·CCl₄、正八面体 SF₆、三角双锥 PCl₅、
  平面正方形 XeF₄）、以及 P₄、S₈ 皇冠环、C₆₀ 富勒烯等结构展示
- 搜索支持化学式、中英文名，以及元素符号（搜 `S` 列出所有含硫分子）
- 详情面板：**作用与生活应用**、摩尔质量、空间构型、组成、键长、简介；
  组成中的元素可点击跳回周期表；理想化几何的分子会明确标注，不冒充实验精度
- 3D 结构：球棍 / 空间填充 / 棍状三种模式，原子标签开关，自动旋转、重置视角、全屏
- 原子按 CPK 惯例着色，化学键在中点分色；双键、三键以平行线绘制

**开屏动画**
- 进站先播一段原子动画，**固定最小播放时长 2.2 秒**（加载再快也会播完），
  进度条与该时长同源，不会对不上
- 动画本身内联在 `index.html` 里，首帧即可绘制 —— 若交给 React 渲染，
  用户会先看到一片空白，再看到"加载中"
- 语言在 React 加载前就从 localStorage 读出，英文用户不会先闪一下中文
- 8 秒兜底：即使 JS bundle 加载失败，也不会把用户永久困在开屏页

**其他**
- 中英文切换（元素名 + 分子名 + 全部界面文案），语言与 3D 偏好持久化到 localStorage
- 深色科技风主题，响应式（桌面优先，移动端详情页以 3D 视图开头）
- 尊重 `prefers-reduced-motion`

## 数据

### 元素

`src/data/elements.json` 由 `scripts/build-data.mjs` 生成，上游数据源
[Bowserinator/Periodic-Table-JSON](https://github.com/Bowserinator/Periodic-Table-JSON)
已固化在 `scripts/source/` 中，因此构建完全离线且可复现。

构建脚本在原始数据基础上做了这些处理：

- **中文名**：补齐全部 118 个元素
- **类别归一化**：上游的 15 种自由文本类别（含 `unknown, probably transition metal`
  一类的推测值）归并为 10 个规范类别。族信息优先于文本描述，因此卤素能从
  `diatomic nonmetal` 中独立出来，超重元素也能落到化学界实际采用的分区
- **电子排布式**：数字转为上标；惰性气体简写式重新生成
  （上游 `electron_configuration_semantic` 存在 `*[Rn] …`、`[Xe] 5d16s2` 等格式不一致）
- **原子半径**：补充 Slater (1964) 经验半径。**97 号及以后元素为 `null`** —— 这些元素
  没有实测半径，编造数值会污染热力图
- **校验**：断言恰好 118 个元素，且每个元素的 `shells` 之和等于其原子序数。
  不满足则构建失败，避免渲染出错误的原子模型

### 用途与应用文案

118 个元素 + 53 个分子，每一条都有中英文的"作用"说明与"生活中的应用"清单，
共 557 条具体应用项。文案单独放在 `scripts/content/` 下，由两个构建脚本合并进
数据文件，并在构建期断言：

- 元素 1-118、全部 53 个分子都必须有条目，缺一个就构建失败
- 中英文说明都不能为空字符串
- 中英文的应用条目数必须一致（漏翻会被抓出来）
- 分子的用途文案不能出现无对应分子的孤立 id

**没有用途的就写没有。** 87 号钫和 99 号以后的合成元素只能以单个原子的规模制得，
半衰期通常不到一分钟，确实没有任何实际应用 —— 这 21 个元素的应用清单是空的，
页面直接显示"目前没有任何实际应用"，而不是编几条把格子填满。类似地，H₂S、NO₂、
CCl₄ 这类在生活中主要以危害或已淘汰用途出现的分子，也照实写。

### 分子

`src/data/molecules.json` 由 `scripts/build-molecules.mjs` 生成。原子坐标不是抄来的
XYZ 数据，而是**由公开的键长与键角构造出来的** —— 这样一处笔误会导致几何校验失败，
而不是产生一个看似合理其实错误的分子。构建期会重新测量并断言：

- 每条键的实测长度与声明的参考键长一致（容差 0.002 Å）
- 声明的键角、二面角与共面性（容差 0.05°）
- 由原子列表反推的组成与化学式一致（按组成而非字符串比对，
  否则 Hill 记法会把 SO₂ 判成 O₂S）
- 非成键原子之间不存在过近距离
- 笼状结构额外校验连接性：C₆₀ 必须恰好 90 条键、每个碳恰好 3 配位 ——
  仅看坐标的话，错误的点云同样"看起来像个球"

这套校验抓到过三个真实 bug：

1. 过氧化氢的二面角被构造成了补角（68.5° 而非 111.5°），因为方位角助手在轴反向时
   会翻转参考系。键长校验发现不了，角度校验可以。
2. 萘的两个稠合碳被重复计入，导致两对原子距离为 0 —— 非成键距离校验直接报了出来。
3. 硝酸的 N—O—H 角度断言写错了顶点（写成以 N 为顶点），实测 30.3° 立刻暴露。

少数分子（C₆₀、萘、尿素）采用理想化多边形几何，数据中带 `idealized` 标记，
详情页会明确提示，避免三位小数的键长暗示实际不存在的实验精度。

## 实现要点

**3D 性能**
每个电子层是一个 `InstancedMesh`，实例矩阵只在电子数变化时写入一次；动画通过旋转父级
`group` 完成，而不是逐帧重写矩阵。最重的元素（Og，118 个电子、7 层）约 17 个 draw call、
约 1.9 万个三角形。

切换元素时 `<Canvas>` **不会**被重新挂载（组件未按元素 key），场景只更新自身内容，
因此不会在每次点击时丢失并重建 WebGL 上下文。已验证：走完全部 118 个元素后，
页面上始终只有 1 个 canvas，且无任何控制台报错。

**相机取景**
`fov` 是垂直视场角，竖长的画布水平可视范围更窄。相机距离按
`min(1, aspect)` 归一化，取两个轴中更紧的一个，否则窄面板会把最外层电子层裁掉。
这段逻辑放在 `src/lib/camera.ts`，原子视图和分子视图共用 —— 它出过一次 bug，
不适合复制两份。

**分子键的绘制**
每条键在中点断开、两半分别用相邻原子的颜色，这样不开标签也能看出组成。同种元素
之间的键跳过分色、只画一根，C₆₀ 的圆柱数量因此减半。双键、三键的平行线沿构建期
算好的垂直方向偏移，该方向取自与相邻键共面的平面，因此苯、乙烯这类平面分子的
多重键会落在分子平面内，而不是垂直翘出去。

**开屏动画的交接**
最小播放时长的唯一定义在 `index.html` 的内联脚本里，同时写进 `window.__SPLASH_MIN_MS`
和 CSS 变量 `--splash-duration`，所以进度条动画和实际等待时间不可能各说各话。
`src/lib/splash.ts` 只负责决定**何时**调用页面已经装好的隐藏函数：等到 App 真正绘制
完成（连续两次 rAF，单次 rAF 早于其后的那次绘制）之后，再补足剩余的最小时长。

**分子渲染的几何复用**
球和圆柱各只创建一份单位几何，尺寸完全由 `scale` 表达；材质按元素缓存。若在每个
mesh 里内联声明 `<sphereGeometry>`，光 C₆₀ 就会分配 150 份几何。这些几何是通过 prop
传入的，three 不会替我们回收，因此组件卸载时手动 dispose。

**已知限制**
- 104–118 号元素的中文名使用 CJK 扩展 B/C 区罕见字，缺少相应字体的系统会显示为方框。
  已在 CSS 中优先声明 Noto / 思源黑体，英文名始终可用作后备。
- 中子数由标准原子量四舍五入得出，对应最常见同位素，并非同位素表。
- 主题为固定深色，未实现浅色主题切换。
- 臭氧、二氧化氮、苯、萘画的是单一路易斯结构（凯库勒式），实际为共振离域，
  详情页已注明。C₆₀ 全部按单键绘制，实际 6-6 键为双键。
- C₆₀（60 原子 / 90 键）是最重的分子模型：约 150 个 draw call。同样受限于无 GPU，
  真实帧率未能在本机验证。
- 元素的英文维基简介未作翻译（已明确标注来源并附链接）；中文侧的原创内容集中在
  「作用与用途」一节。
- 用途文案让首屏包增加约 40 KB（gzip）。考虑到开屏动画本身要播 2.2 秒，
  这部分下载基本被掩盖，因此未做拆包懒加载。
- 分子构型取自气相实验值，乙醇等可旋转单键的分子只展示一种构象。
- 60fps 指标未能在本机验证：容器内没有 GPU，SwiftShader 软件渲染下即使是单电子场景
  也只有约 19fps。上面的 draw call 与三角形数量是可核对的替代依据。
